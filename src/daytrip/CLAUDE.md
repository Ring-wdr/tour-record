# 당일 여행 페이지 (src/daytrip/)

단신 여행 = `isFeature(trip)`가 false인 여행(국내 당일, 또는 trip.yaml `feature: false`). 라우트 `src/pages/trips/[slug]/index.astro`가 `DayTripPage.astro`를 렌더한다. 이 폴더는 그 한 페이지만을 위한 독립 프로젝트처럼 다룬다. 사이트 공용 파일(`src/lib/trip.ts`, `src/layouts/Base.astro`, `global.css`)은 **읽어서 쓰기만** 하고, 피처 여행 페이지 동작을 바꾸지 않는다. 예외: 목록의 단신 줄 `src/components/TripBrief.astro`는 이 페이지의 입구라서 `lib.ts`·`sky.ts`를 가져다 쓴다(아래).

## 설계 원칙 — "하루의 빛"
- **스크롤 = 시계.** 페이지를 내려가는 것이 그날 아침에서 저녁으로 가는 것. 화면 가운데 선이 지나는 자리의 시각이 분 단위로 흐른다(장소 머리·사진·장소 끝마다 시각 기준점, 그 사이는 보간). 그래서 **사진은 늘 시간순으로 놓인다** — 같은 장소 안에서도 늦게 찍은 사진이 먼저 나오면 필름 각인이 거꾸로 읽힌다(12:56 → 12:54). 작은 사진의 자리도 시각으로 정한다(아래 편집 필드).
- **색 = 시각의 빛.** `sky.ts`의 팔레트(새벽 보라 → 아침 푸른빛 → 늦은 오전 물빛 → 한낮 전 연둣빛 → 한낮 맑은 금빛 → 이른 오후 짙은 금빛 → 늦은 오후 호박·주황 → 해 질 녘 붉은 주황 → 노을 장밋빛 → 저녁 보랏빛 → 밤 남색)를 모든 당일 여행이 같이 쓴다. 타임라인 시각·척추 선·지도 경로 선·시계 막대·배경 하늘·코다와 목록의 빛 띠가 전부 이 색. 여행마다 바꾸지 않는다(여행 고유색은 dayXX.md `tone` — 목록 눈썹 글자·플레이스홀더·지도 포커스 테두리에만). 아침 쪽 배경은 일부러 진하게(08:20 푸른빛, 10:00 물빛), 오후는 한 시간 반마다 색상(노랑 → 주황 → 빨강 → 자홍)과 밝기가 분명히 바뀌게 — 12~16시가 같은 흙빛으로 뭉개지지 않게(리뷰 지적).
- **피처 여행을 복제하지 않는다.** DayRail·날짜 타이틀 카드·여행 전체 고도 그래프·배경 고정 지도 스크롤리텔링은 쓰지 않는다. 대신 매거진 단신/포토 에세이의 밀도: 여는 면 → 지도 한 장 → 시간순 기록 → 종이 일기 → 코다.
- **사진 편집에 위계를 둔다.** 모든 장소를 같은 틀로 두지 않는다 — 하루에 한두 번 페이지 폭 가득한 장면(`size: full`), 표지판·기록 사진·셀카·같은 음식의 두 번째 컷은 작게(`size: small`), 빈 하늘이 많은 사진은 잘라서(`crop`). 본사진은 한 장이든 여러 장이든 같은 측정폭(글 열 전체)을 채운다 — 단독 사진만 좁으면 오른쪽에 빈 띠가 생긴다.
- **글의 역할을 나눈다.** 장소 노트 = 실린 사진에 보이는 사실만 짧게. 사진에 없는 이야기(다른 사진에만 있는 장면, 이동, 귀가)는 일기 본문에. **같은 문장을 두 번 쓰지 않는다** — 캡션도 마찬가지라 화면에 보이는 캡션은 dayXX.md에 `caption`을 따로 적은 사진만(짧은 명사구, 노트에 없는 것). 나머지는 시각 각인만 보이고 alt는 대체 텍스트·크게 보기에만. 일기에 편집 과정(“몇 장 중 몇 장을 골랐다”)을 드러내는 메타 문장은 쓰지 않는다.
- **여행 고유 문구·값은 콘텐츠에서만.** 컴포넌트는 `trip`/`day`/`moments`를 prop으로 받는다. 다음 당일 여행도 같은 페이지로 나와야 한다. 고정 문구(“지도 위의 하루”, “사진 없는 구간”, “End of the day” 등)는 어느 당일 여행에도 맞는 말만.
- 사이트와 한 가족: `global.css` 토큰·폰트(Fraunces 큰 숫자·지명·라틴 글자, Noto Serif KR 제목·본문, Pretendard UI, JetBrains Mono 데이터·시각, Nanum Pen Script 손글씨 메모), 어두운 필름 톤 + 종이.
- **사진 색**: 휴대폰 사진의 쨍한 파랑·초록이 어두운 필름 톤과 부딪치지 않게 페이지의 모든 사진(표지 포함)에 가벼운 보정 `--dt-grade`(`saturate(0.88) sepia(0.08)`, `DayTripPage.astro`의 `.dt-page`). 사진 파일은 그대로(다른 페이지·크게 보기는 원본 색). 표지의 입장 연출 `settle` 끝 값도 같은 함수 목록이라 보정을 바꾸면 거기도 본다.

- 데이터 모델: `lib.ts`(서버 전용) — `moments()`(장소 → 시간축의 순간: 분·색·번호 `n`(끝줄은 0)·`bookend`·다음까지 `gap`(머리→머리)·`last`(장소 끝 시각)·`move`(last→다음)·`jump`·사진 시각·비율), `numbered()`, `coverOf()`, `facts()`, `routeLines()`(경로 + 진행률별 색 + `parts`(실선/점선/장소끼리 이은 가는 선 `link` 토막) + `legs`(점선으로 끊긴 구간별 번호)), `detailLeg()`(확대 칸 구간), `scriptRuns()`(라틴 글자 덩어리), `sunArc()`, `isoAt()`. `sky.ts`(import 없는 순수 함수, 서버·브라우저 공용).
- **장소 수는 한 가지 정의**: 번호 붙은 장소(`numbered()` — 끝줄 제외, 첫 장소가 사진 있는 arrival이면 포함) = 지도 번호 = 범례 = 여는 면 Stops = 일기 메모 “N곳” = 목록 “N stops”. 시간축(Hours, 하루의 호, 시계 막대 눈금, 빛 띠, 코다 시각)은 끝줄까지 포함. 공용 `tripStats().places`(도착·출발 제외)는 피처 목록용이라 여기서는 쓰지 않는다.
- 끝줄 조건: 장소가 3곳 이상이고, 맨 앞이 사진 없는 `arrival`이거나 맨 뒤가 사진 없는 `departure`. 사진이 한 장이라도 있으면 번호 붙은 장소다.
- 사진 없는 구간: `pnpm tracks` 궤적에서 한 구간(사진과 사진 사이)이 max(700m, 구간 길이 중앙값×5)보다 길면 점선. 궤적 없이 장소를 이은 날은 나누지 않는다. 점선이 다른 토막을 가로지르면 2차 곡선으로 휜다(`arcFor` — 휘는 정도 ±0.45×현 길이 후보 중 엇갈림 없고 장소에서 현 길이 7% 넘게 떨어진 것, 같으면 덜 휜 것). 어차피 지나간 길을 모르는 구간이라 “곧게 이은” 선일 필요가 없다 — 지도 설명도 “지나간 길을 모르는 구간”.

## 콘텐츠 규칙 (당일 여행용 trip.yaml / dayXX.md)
- `country: Korea` + `start = end`면 자동으로 단신. 다른 경우 `feature: false`로 강제 가능(여러 날도 렌더는 되지만 당일 기준 설계).
- day01.md에 `fromBase: false` — 집(출발·귀가)은 사진에도 사이트에도 없다. 경로는 첫 장소에서 시작해 마지막 장소에서 끝난다.
- 장소 `time`이 시간축의 기준. 없으면 첫 사진 파일명 시각, 그것도 없으면 앞뒤 사이.
- **따옴표는 ‘ ’ “ ”를 직접 쓴다.** 곧은 따옴표(')를 쓰면 일기(마크다운 smartypants)는 한글 앞 '를 닫는 따옴표(’)로 바꾸고, 노트(frontmatter)는 곧은 따옴표 그대로라 한 페이지에 두 체계가 섞인다.
- **사진 시각은 파일명 `YYYYMMDD_HHMMSS`에서 읽는다**(`photoMinutes`). 휴대폰 시간대 = 현지인 국내 여행 전제. 파일명 규칙이 다르면 각인이 안 붙을 뿐 페이지는 된다.
- 장소 이름(`name`)은 타임라인 제목·지도 범례·시계 막대(“A → B”)·지도 이름표에 그대로 나온다 — 가게 간판 이름만 쓰면 여행 이름처럼 읽힐 수 있으니 무엇인지 드러나게(“점심, 고석정 나들이”). `nameEn`은 번역 이름(설명문 “Heading Home” 같은 것은 쓰지 않는다).
- **사진 편집 필드**(`src/schemas/trip.ts` photoSchema, 선택 — 피처 페이지는 무시):
  - `size: full` — 페이지 폭 가득. 장소의 사진 중 **맨 뒤**에 모아 한 줄(연속된 full끼리 나란히). 그래서 그 장소에서 가장 늦게 찍은 사진이어야 시간순이 맞는다. 하루에 한두 번만. 좁은 화면에서는 한 장씩 가장자리까지 쌓이고, `crop` 없는 가로 사진은 5:4보다 납작하지 않게 가운데를 높게 잘라 보인다(한 장의 무게가 남게 — 피사체가 가운데서 멀면 `crop`으로 직접 자른다).
  - `size: small` — 작게(데스크톱 ≈260px, 좁은 화면 노트 옆 64% 폭·본사진 뒤 46% 폭). 표지판·이름표·기록 사진·셀카·같은 음식의 두 번째 컷. **자리는 시각으로**: 그 장소의 첫 큰 사진(보통, 없으면 전폭)보다 이르거나 같으면 노트 옆, 늦으면 본사진 오른쪽 짝(좁은 화면은 본사진 아래). 본사진이 없으면 노트 옆.
  - `crop: [왼쪽, 위, 폭, 높이]` — 원본 기준 %. 페이지에서는 그 부분만(칸 비율 = 잘라 낸 부분 비율), 라이트박스는 원본 전체. 비율이 바뀌면 같은 장소 사진들의 줄바꿈도 바뀐다(본사진 줄바꿈 기준 높이 `--row-h` 240px — 16:9 + 21:9 두 장이 글 열 한 줄에 들어간다). 빈 하늘을 덜어 내거나(21:9 등) 세부를 확대(1:1)하거나 세로 사진을 4:5로(전폭 한 쌍에서 빈 하늘이 화면을 채우지 않게).
  - `trim: [왼쪽, 위, 폭, 높이]` — 원본 기준 %. **공개 파일 자체를 그 부분만 잘라 만든다**(`pnpm photos` 변환 단계, 라이트박스도 잘린 사진). 사람·번호판처럼 공개하면 안 되는 부분을 뺄 때. `crop`은 화면에서만 잘리고 라이트박스는 원본 전체라 프라이버시용으로 쓰면 안 된다. trim한 사진에 crop을 또 걸면 crop은 잘린 파일 기준.
  - `caption` — 화면에 보이는 짧은 설명. 노트에 없는 것만(“강물에 깎인 바위섬”, “안내판 앞에서 셀카 한 장”). 없으면 각인만.
- 표지(`cover`)는 장소 사진과 겹치지 않게 고른다(타임라인에 두 번 나오지 않도록). 캡션은 파일명 시각 + 그 시각에 있던 장소로 자동.
- `approx: true`는 데이터·TODO로만 남긴다 — 이 페이지에는 "좌표·이름 확인 필요" 배지를 **표시하지 않는다**(사용자 요청, 개발 서버 포함).
- 고도는 선택. 한국 GPS 고도는 타원체 기준(약 +25m) → 공식 값 없으면 GPS 중앙값 − 25로 적거나 생략.
- 사진이 없는 짧은 경유지(아치·표지판 하나)는 장소로 세우지 않는다 — 번호·여백만 늘린다. 필요하면 이웃 장소 노트나 일기에 한 줄. 하루를 여닫는 사진 없는 도착·출발(주차장 등)은 장소로 적되 끝줄로 보인다.

## 주의점
- MapLibre 컨테이너(`#dt-map`, `.detail-map`)는 자식이 없어야 한다 → 대체 SVG·확대 칸·잇는 선은 형제 요소.
- `zoom` 식은 맨 바깥 `interpolate`/`step`의 입력으로만 — `case` 안에 넣으면 레이어가 통째로 실패한다. `line-gradient`는 `line-dasharray`와 같이 못 쓴다 → 점선 토막은 따로 한 가지 색 레이어.
- 지도 점 id는 순서 `k`(1부터) — 번호 `n`은 끝줄이 0이라 겹칠 수 있어 feature id로 쓰지 않는다(`setFeatureState`).
- 카메라 이동: `flyTo`에는 `padding`을 쓰지 않는다(루트 CLAUDE.md). 전체 보기·확대 칸 구간 보기는 `fitBounds`의 padding만.
- `map.on('error')`를 반드시 붙여 둔다(`newMap()`) — 듣는 쪽이 없으면 타일 하나 실패도 `console.error`. 스프라이트에 없는 무늬(wood-pattern)는 `setMissingStyleImageResolver`로 1px 빈 그림.
- 지도 안 저작권은 접어 두고(ⓘ), 지도 칸 아래 크레딧 줄을 늘 보인다. ⓘ 버튼은 filter(invert)가 걸려 있어 포커스 테두리를 바깥 details에 그린다.
- View Transition: `<link rel="expect" href="#trip-hero" blocking="render">`(head 슬롯), `html.vt-from-list`면 첫 화면 입장 연출(사진 현상·글자 떠오르기·호 그리기) 전부 생략, 지명에 `view-transition-name: dt-title`을 줘서 표지가 커지는 동안에도 지명이 사진 위에 있게. 그 지명은 목록 화면이 거의 사라진 뒤 나타난다(`::view-transition-new(dt-title)` 0.4s 지연 — 전환 첫 순간 목록의 피처 제목과 글자가 부딪치지 않게). 여는 면 사진 칸 비율은 화면 높이에 따라 변한다(1440×900 ≈ 1.38, 390 폭 5:4) — 목록 썸네일 비율(4:3 / 5:4)을 바꾸면 같이 본다.
- **척추는 `.main::before`**(점 아래 ~ 글·사진 끝)와 `.move::before`(여백)로 나뉜다. 전폭 사진 줄이 있는 장소(`.has-bleed`)는 척추가 `--bleed-gap`만큼 내려가 사진 위 끝 밑으로 들어가고, 전폭 사진·캡션 구간에는 선이 없다(캡션 글자 위로 선이 지나가지 않게). 전폭 줄의 위 여백을 바꾸면 `--bleed-gap` 하나만.
- sticky 겹침: 시계 막대 높이 ≈ 60px(데스크톱)·70px(모바일) → 장소 `scroll-margin-top` 84/88px, 시각 열 `top: 92px`(데스크톱만). 막대 높이를 바꾸면 같이 고친다. 시각 열 sticky는 `.main` 격자 안에서만(크롬은 격자 항목 sticky를 격자 컨테이너로 제한 — 전폭 줄·여백은 `.main` 밖 형제라 시각이 전폭 사진 전에 멈춘다). 모바일 지도 sticky(z-index 3)는 지도 섹션 안에서만.
- 여백의 정시 눈금 위치 = (정시 − 장소 끝 시각) / (다음 장소 시각 − 장소 끝 시각). 스크롤 시계도 장소 끝(`data-last`)부터 다음 장소 머리까지 같은 비율로 흘린다 — 한쪽을 바꾸면 다른 쪽도. 여백 높이·“+ 40m”도 같은 구간(`m.move`).
- `prefers-reduced-motion`: 전역 규칙이 애니메이션을 끄고, 스크립트는 경로 그리기·flyTo 시간을 0으로(확대 칸은 바로, 경로는 처음부터 다). 떠오르기는 처음부터 보인다.
- **개발 서버와 스키마**: `src/schemas/trip.ts`를 고쳐도 떠 있는 개발 서버의 content layer는 옛 스키마로 md를 검증한다(새 필드가 조용히 잘림). `touch`로는 안 되고 `src/content.config.ts` **내용**이 바뀌어야 "Content config changed"로 다시 읽는다. 운영 빌드는 상관없음.
- 개발 중: `.astro`를 고친 직후(node 스크립트든 편집기든) Vite CSS 모듈이 옛것으로 남는 경우가 있다(SSR HTML은 새것, 브라우저 스타일시트는 옛것) → 파일을 `touch`. 이 폴더 파일은 줄 끝이 CRLF·LF로 섞여 있다 — node로 여러 줄을 바꿀 때는 `.scratch/cheorwon/r4/rep.cjs`(줄 끝을 지킨다). 저장소 안(.scratch 포함)에 `.html`을 쓰면 개발 서버가 감시해 페이지를 새로고침한다 → HTML 덤프는 저장소 밖에.
- 확인: `playwright-cli -s=build`(세션이 없으면 `open`을 백그라운드로 띄우고, 이후 `goto`/`resize`/`screenshot`/`run-code --filename`). 결과 풀어 보기 `node .scratch/cheorwon/r4/run.cjs <script.js>`, 가로 넘침 `r4/overflow.js`(320~1920), 콘솔 `r4/console.js`, CLS `r4/cls.js`, 감속 모션 `r4/rm.js`, 크게 보기 `r4/lb.js`, 목록→페이지 전환 프레임 `r4/vt.js`, 스크린샷 스크립트 `r4/shots.mjs`(+ 밀착 인화 `r4/sheet.mjs`), 스크린샷 `.scratch/cheorwon/shots/`. 저장소 루트에 생기는 `.playwright-cli/`는 끝나면 지운다. 작업 노트 `.scratch/cheorwon/notes-designer.md`.
- **draft 여행 운영 빌드 확인**: `pnpm build`는 draft를 빼므로 철원 페이지가 안 만들어진다. 파일을 고치지 말고 `pnpm astro build --devOutput --outDir .scratch/<slug>/dist-verify`(git 제외 폴더. 저장소와 같은 드라이브여야 한다 — 다른 드라이브면 에셋 옮기기가 EXDEV로 실패)로 만들어 확인 — `/trips/<slug>/index.html`이 생기는지, HTML에 비공개 좌표(git 제외 파일 trips.local.json의 zones — 값은 그 파일에서 읽고 여기 적지 않는다)가 없는지 grep. devOutput은 개발 모드라 “좌표·이름 확인 필요” 배지가 들어 있는 게 정상. 확인 뒤 임시 폴더 삭제.
